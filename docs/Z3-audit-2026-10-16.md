# Z3 integratie-audit — 16 oktober 2026

Status: **Node production path verified; Bun runtime incompatible (observed); failure policy still design-open.**

## Werkelijk uitgevoerd

- GitHub Actions [real Z3 audit](https://github.com/E-AI-MODEL/eainesy/actions/runs/38964644310).
  - The actual `src/lib/eainesy/z3cert.ts` (bundled without replacing Z3) was executed under Node with the real `z3-solver`.
  - **79/79 tests passed, 0 skipped; 598.5 ms summed solver time**. Matrix: risk/confidence thresholds, both directions of max-fusion, intentionally inconsistent risk/fusion/band, numeric bounds and policy-vs-numeric bands.
  - Direct execution of the production certificate under **Bun 1.3.4** hit `Aborted(Assertion failed)` in the WASM pthread worker and hung until killed after 40 s. This is **not** proof that every Bun version or deployment will fail.
- GitHub Actions [Node standalone startup](https://github.com/E-AI-MODEL/eainesy/actions/runs/38964873103): Next.js standalone boot and `/api/verify` passed.
- GitHub Actions [Node end-to-end chat](https://github.com/E-AI-MODEL/eainesy/actions/runs/38965147739): actual built Next.js chat API, synthetic input, SQLite with a stable absolute path. `z3.available=true`, `z3.result=sat` (259 ms in that run), `modelCheck.pass=true`, `outputPolicy.pass=true`. Live GLM service was not exercised or validated.

## Bewijsbereik

1. The `modelchecker.ts` report enumerates a **closed, finite lattice**: 21,600 message-level and 141,120 conversation-level states, 43 declared invariants. This is **not Z3**; it covers the represented states and the encoded predicates, not every possible natural-language conversation or implementation failure.
2. The SMT certificate in `z3cert.ts` asserts numeric consistency of (a) risk score and its ordinal risk level, (b) max of lexical/neural risk levels, and (c) composed confidence and numeric band. `sat` means the asserted constraints are **jointly satisfiable**; it does not prove that the neural reading, lexical markers, intervention choice, textual reply or safety of a live deployment is correct.
3. `unsat` indicates an inconsistent set of asserted arithmetic constraints and `unknown` means the solver could not decide. Production `applyZ3Fallback` maps these to a coherent crisis plan. This mapping is unit tested, but not yet mutation-tested end-to-end with the real solver integrated into an HTTP request.
4. If `init()` fails or the solver throws, `certifyDecision` returns **`skipped`**, and `applyZ3Fallback` **does not override** the decision. This is an *optional/degraded verification* policy, not a strict "solver must certify before output" policy. The exception handler cannot be relied upon to recover from unhandled worker events or a permanently hung solver; no explicit production check deadline is set.
5. The modelcheck report is recorded in the conversation trace and certificate, but the shown `processTurn` path does not visibly block generation when `modelCheck.pass=false`. This must be evaluated before making unconditional formal-verification claims.

## Runtime decision

The checked Node startup configuration is now the default: `NODE_ENV=production node .next/standalone/server.js`.
Bun remains the installer, builder and deterministic test runner with an explicit Z3 mock in `tests/support/preload.ts`; those green Bun tests must **never be described as end-to-end live Z3 coverage**. The independent Node certificate audit and Node HTTP chat test are the live Z3 checks.

The Bun diagnostic in the separate audit workflow is retained and **warns** when incompatible; it does not fail the Node-based release path.

## Nog nodig voordat Z3 als harde verificatiepoort wordt geclaimd

- Explicitly decide whether Z3 availability is mandatory or advisory. If mandatory, design a distinct human-review / abstain path for solver unavailability; indiscriminately invoking a crisis protocol for harmless text is not a sound substitute for error handling.
- Introduce a bounded solver deadline and isolate worker/process failures; test worker crashes and hung initialization.
- Test all four reported statuses (`sat`, `unsat`, `unknown`, `skipped`) through the actual final response and audit certificate, not only `applyZ3Fallback` in isolation.
- Check that the hash and modelcheck failure paths cannot silently permit an unproven rule set.
- Assess live deployment latency, CPU/memory, repeat turns, and concurrency under Node; 79 small solver checks and one chat request are not a load test.
- Review Z3 scope and language in the UI to avoid conflating arithmetic consistency with semantic safety.


## Update: verplichte verificatiepoort

Live automatische HTTP-antwoorden vereisen een geslaagde modelcheck EN een echt Z3-resultaat `sat`. `unsat`, `unknown`, `skipped` blokkeren antwoordgeneratie zonder een crisislabel te verzinnen. De API geeft `failClosed=true`, `action=ABSTAIN_HITL`, `verification.reason` en `humanReviewQueued=false`; er bestaat nog geen automatische menselijke reviewwachtrij. De stop wordt zonder gespreksinhoud gelogd in de auditketen. Preset onderzoeksfixtures blijven gesimuleerd, niet Z3-gecertificeerd.

Er is een vijfseconden responstijddeadline en een 30-seconden circuitpauze. Dit stopt niet gegarandeerd een vastgelopen WASM-worker. Harde procesisolatie en piekbelastingstests zijn openstaande eisen; maak geen formele veiligheidsclaim zolang die ontbreken.
